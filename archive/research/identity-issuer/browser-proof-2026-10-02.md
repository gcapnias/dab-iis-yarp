# Local issuer browser proof, 2026-10-02

The Windows workstation's installed Edge browser ran `scripts/identity-issuer-browser-check.js` against a freshly started local Kestrel issuer. The CLI used `requests/playwright-cli.iis-test.config.json`, including `ignoreHTTPSErrors: true`; this test bypasses certificate trust and hostname validation and does not validate production TLS. No certificate was installed or trusted, no machine policy was changed, and no software was installed.

On the fresh issuer build, the browser checks passed for anonymous discovery and issuer match, Windows request identity/SID availability booleans, antiforgery cookie security, missing-CSRF rejection, session creation, HttpOnly cookie invisibility, access and refresh cookie Secure/SameSite/path/expiry attributes, host-only scope, sequential refresh-cookie rotation, stale refresh replay rejection, and logout cookie removal. In particular, a second refresh succeeded after the first rotation, confirming the browser stored the replacement cookie at the issuer root path; replaying the first token was rejected. Cookie values, bearer tokens, request headers, account data, SID, and profile data were not emitted or persisted.

The OIDC authorization endpoint returned a code in the browser. Playwright's navigation to the registered test callback left the issuer origin, and navigating back to the issuer failed before the browser harness sent the token exchange request. Therefore this run does not claim browser token exchange, ID/access token validation, or OIDC refresh. Those protocol checks remain covered by the existing PowerShell live HTTP harness and the Release automated suite. The browser script records this limitation without exposing the code or callback URL.

The separate IIS browser verifier and framework-dependent publish script are ready for the Windows Server test environment. IIS execution is tracked by [issue #12](https://github.com/gcapnias/dab-iis-yarp/issues/12); no IIS components were installed or enabled on this workstation.

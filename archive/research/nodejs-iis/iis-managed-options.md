# IIS-managed Node.js hosting options

Research snapshot: 2026-10-13. This note compares IIS modules that can start or route to Node.js processes. It records documented behavior and maintenance evidence; it does not select an architecture or provide a deployment recipe.

## Existing research

A search of the current `archive/research/` tree found no prior Node.js/IIS hosting research. Existing notes discuss IIS Windows Authentication for ASP.NET Core, which does not establish Node.js behavior.

## Evidence and boundaries

### HttpPlatformHandler

Microsoft describes HttpPlatformHandler as an IIS 8+ module for process management of HTTP listeners (including Node.exe) plus request proxying. The application receives the chosen listener port through `%HTTP_PLATFORM_PORT%`; Microsoft's sample shows a listener configured from that variable. The configuration reference documents process startup/retry, process count, logging, environment variables, recycle-on-file-change, and optional Windows token forwarding. The token forwarding contract is low-level: the child process receives a token handle per request and must call `CloseHandle` for every request. This makes native token handling a deliberate application integration task, not a Node framework feature.

### iisnode

The Azure/iisnode repository README says it hosts Node applications in IIS, lists Node and IIS prerequisites, and states WebSocket functionality requires IIS 8.x on Windows 8 or Windows Server 2012. Its sample `web.config` documents per-application process count, watched files, graceful shutdown, request concurrency, and the `promoteServerVars` mechanism. That sample is under the original `tjanczuk/iisnode` upstream path; Azure's repository history/fork is the maintained lineage described by the upstream notice. The very old platform prerequisites and latest release date are maintenance signals, not a formal deprecation announcement.

### Windows Authentication boundary

For either module, enabling Windows Authentication at IIS only establishes authentication at the IIS edge. The application needs a supported identity handoff and validation contract. HttpPlatformHandler documents an opaque native token handle header (opt-in); iisnode documents selected IIS server variables becoming request headers. Neither reviewed contract says Node receives a Windows principal or automatically impersonates the user. Never trust a client-supplied identity header; configure IIS to overwrite/remove any colliding inbound header, and constrain direct access to the backend listener.

### Evidence limits

- The Microsoft HttpPlatformHandler article was last updated 2020-05-14. The separate Microsoft Supported Downloads listing is a positive generic support signal, but the module page does not specify Windows Server 2025 coverage; see [component maintenance evidence](component-maintenance.md).
- iisnode release history lists v0.2.26 (2017); the repository history page shows changes in 2022/2023 that are mandatory repository-policy files. This is not evidence of an official deprecation, nor enough to establish current security/support status.
- The iisnode WebSocket documentation names only IIS 8.x and Windows 8/Server 2012. It should not be generalized to current versions without a compatibility test.
- WebSocket behavior for HttpPlatformHandler and current ARR reverse proxy behavior were not established from a sufficiently specific current primary-source contract in this pass.
- No repository file in `archive/research/` contained previous Node.js/IIS hosting findings.

- [Azure/iisnode releases](https://github.com/Azure/iisnode/releases) — latest listed release and release notes.
- [Azure/iisnode commit history](https://github.com/Azure/iisnode/commits/master/) — dated history, including 2022/2023 policy-file commits and older functional commits.
- [iisnode configuration sample](https://github.com/tjanczuk/iisnode/blob/master/src/samples/configuration/web.config) — process count, shutdown, logging, watched files, and `promoteServerVars` behavior.
- [iisnode Hello World sample](https://github.com/Azure/iisnode/blob/master/src/samples/helloworld/readme.htm) — Node binds to `process.env.PORT` when hosted in iisnode.
- [Microsoft IIS WebSocket Protocol Support](https://learn.microsoft.com/en-us/iis/configuration/system.webserver/websocket) — IIS WebSocket feature configuration. This does not itself prove that a particular proxy/module forwards WebSocket upgrades.
